# Архитектура v9 — «точность прежде всего»

## 1. Что было сломано в v8

Отчёт от 10.09.2026: служба одновременно **не находит** реальных ошибок и
**портит** корректный текст. Эталонный пример из отчёта:

```
… проставляются в соответствующий раздел журнала …
→ … проставляются в соответствующего раздел журнала …
```

Дефект воспроизведён локально на коде из `main`. Первопричины — три, и
они усиливали друг друга.

### 1.1. Правило согласования с нулевой точностью

`local_rules._modifier_noun` работал по схеме «взять `parse[0]` вершины,
подогнать определение через `inflect({case, number, gender})»`:

* **омонимия падежей не разрешалась.** У «раздел» pymorphy3 даёт `accs`
  (score 0.50) и `nomn` (0.43). Выбор первого разбора объявлял
  винительный падеж единственно верным, и согласованная пара признавалась
  ошибкой;
* **`inflect` вызывался без грамммемы одушевлённости.** Для мужского рода
  в винительном падеже это возвращает одушевлённую форму, совпадающую с
  родительным: «соответствующий» → «соответствующего». Это и есть
  дефект из отчёта;
* **не проверялось, согласована ли пара уже сейчас.** Код перебирал
  разборы до первого, дающего *отличающуюся* форму, т.е. был системно
  смещён в сторону порождения правки;
* краткие формы (ADJS/PRTS) считались определениями: «Утвержден план» →
  «Утверждённого план»;
* словарь всегда отдаёт формы с «ё», поэтому вместе с падежом менялась
  орфография: «отчетный» → «отчётного».

Замер на восьми заведомо корректных официально-деловых предложениях:
испорчено шесть. На полном корпусе из 70 предложений (`eval/cases.jsonl`)
— **испорчено 49**, т.е. 70 % корректного текста.

### 1.2. Grammar gate превращал одну ошибку в отказ всей системы

```python
LOCAL_GRAMMAR_GATE_CATEGORIES = "rule-quantifier,rule-government,rule-agreement"
...
if gate_hit:  # достаточно одного кандидата rule-agreement
    logger.info("Grammar gate hit: skipping expensive GEC specialist")
```

Gate отключал и GEC-специалиста, и обе rescue-модели. Поскольку правило
согласования срабатывало ложно почти на любом тексте, в журналах
прод-сервера gate срабатывал на **каждом** запросе:

```
stages={'rules': 1, 'sage': 1, 'gec': 0, 'draft_tlite': 0, 'draft_giga': 0}
```

То есть Qwen3.5-GEC, T-lite и GigaChat не вызывались ни разу. Служба
работала как «сломанное правило + SAGE».

Архитектурная ошибка здесь общая: gate экономил вычисления на основании
**непроверенных** кандидатов. Решение о пропуске дорогой стадии нельзя
принимать до валидации.

### 1.3. Антигаллюцинационный фильтр был мёртвым кодом

```python
if not c.category.startswith(("model", "unknown", "languagetool", "surface")):
    return False
```

Реальные категории v8-стека — `sage-spell-punc`, `russian-gec`,
`draft_tlite`, `draft_giga`. Ни одна не попадает под префиксы, поэтому
`DecisionEngine._is_unverified_llm_inflection` не проверял ничего. Любая
падежная фантазия SAGE проходила с уверенностью 0.90.

### 1.4. Сопутствующие потери

| Проблема | Следствие |
|---|---|
| Правка адресовалась поиском подстроки, при `len(positions) != 1` молча отбрасывалась | терялись все правки неуникальных слов («раздел», «в», «и») |
| Посимвольный diff | правка «вида→видов» превращалась в `«а» → «ов»`, неуникальна → отбрасывалась |
| Ответ модели шёл в diff без нормализации | «Исправленный текст: …», ``` ```, `<think>` → глобальный diff → ноль кандидатов |
| Весь фрагмент одним запросом в SAGE-95m | модель обучена на одиночных предложениях, на абзаце перефразирует → `_global_rewrite` → ноль кандидатов |
| Retrieval (2135 пар) подключён только к rescue | самая маленькая модель (0.8B) работала без few-shot |
| `AsyncClient` на каждый вызов | новое TCP-соединение на стадию |
| `pymorphy3.MorphAnalyzer()` внутри фильтра | загрузка 50 МБ словарей на каждую правку |
| Нет метрики качества | регрессия точности прожила четыре релиза |

## 2. Архитектура v9

```
                            текст + контекст
                                   │
                        segmentation (предложения + смещения)
                                   │
      ┌──────────────┬─────────────┼──────────────┬───────────────┐
      │              │             │              │               │
 LocalRuleEngine  Dictionary   LanguageTool      SAGE        Qwen3.5-GEC
 (морфология,     SpellChecker (пунктуация,   (орфография,   (грамматика,
  доказуемо)      (словарь)     типографика)   пунктуация)    few-shot)
      │              │             │              │               │
      └──────────────┴─────────────┴──────────────┴───────────────┘
                                   │
              rescue (T-lite / GigaChat) — только если ничего
                                   │      не подтверждено
                        CandidateArbiter (голосование, слияние)
                                   │
                        GenerativeGuard (классовый фильтр)
                                   │
                        DecisionEngine (адресация по смещению,
                                        защищённые термины, лимиты)
                                   │
                            точные правки + ===CHANGES===
```

Принципы:

1. **Любая омонимия трактуется в пользу исходного текста.** Если
   существует хотя бы одно прочтение, при котором фраза корректна, — она
   корректна.
2. **Детерминированное вперёд, генеративное потом, gate — никогда.**
   Дешёвые доказуемые стадии выполняются всегда; дорогие модели
   отключаются только по подтверждённому результату.
3. **Правка от одной генеративной модели без подтверждения не
   применяется.** Классический system-combination из GEC.
4. **Качество измеряется.** CI-гейт запрещает мерж при росте FP на
   корректном тексте.

## 3. Модель согласования (`np_agreement.py`)

Именная группа — набор токенов с множествами прочтений
`(падеж, число, род, одушевлённость)`. Ищется присваивание признаков,
согласованное с максимальным числом токенов. Правка предлагается только
при **единственном** лидирующем присваивании и **ровно одном**
несовместимом токене.

Источники ограничений:

| Источник | Пример |
|---|---|
| Род и одушевлённость вершины (лексические факты) | снимает дефект `inflect({accs, sing, masc})` |
| Управление однозначного предлога | «согласно утверждённому **плана**» → «плану» |
| Краткая форма сказуемого (подлежащее в им. п.) | «**Проверочное мероприятия** проведено» → «мероприятие» |
| Именное управление слева | «факт **несвоевременное** оформления» → «несвоевременного» |
| Наименее омонимичный токен (при равной поддержке) | «на **текущий года**» → «текущий год» |

Многозначные предлоги («в», «на», «по», «с», «за», «под», «между») в
таблицу управления **не включены**: они дают не ограничение, а ложные
срабатывания.

Закрытые классы ложных срабатываний:

| Класс | Пример | Признак отсечения |
|---|---|---|
| Обособленный причастный оборот | «ущерб, причинённый подразделению» | запятая перед причастием либо согласование с существительным слева |
| Предикативный творительный | «назначенный **ответственным** сотрудник» | все сопоставимые прочтения в твор. п., вершина твор. п. не принимает |
| Субстантивированное местоимение | «**при этом** количество…» | Apro без `Anum` после однозначного предлога |
| Омонимичное существительное как определение | «с **данными** бухгалтерского учёта» | есть NOUN-разбор и нет согласования |
| Однородный ряд при вершине в мн. ч. | «для первого и третьего **отделов**» | союз в ряду → число не правим |
| Местоимённое прилагательное как вершина | «по одной и той же теме» | Apro-разбор не может быть вершиной |
| Зависимая генитивная группа при сказуемом | «Результаты контрольной проверки признаны…» | сказуемое относится к существительному слева |
| Безличный пассив с отрицанием | «нарушений **не выявлено**» | отрицание перед краткой формой |

## 4. Орфография без моделей (`spellcheck.py`)

1. слова нет в словаре OpenCorpora → кандидат на опечатку;
2. правки на расстоянии Дамерау—Левенштейна 1 фильтруются по словарю;
3. отбрасываются нестандартные формы по стилистическим пометам
   OpenCorpora (`V-be`, `Arch`, `Erro`, `Infr`, …) — «подразделенья» не
   конкурирует с «подразделения»;
4. при нескольких вариантах включается разбор по контексту: вариант
   должен согласоваться с вершиной именной группы — «нормативых» →
   «нормативных», потому что только эта форма согласуется с «актов»;
5. правка применяется лишь при единственном выжившем варианте.

Пропускаются аббревиатуры (`ГУВД`), имена собственные внутри
предложения, слова из пользовательского словаря и дефисные образования.

Цена: DAWG-lookup ≈ 19 мкс; слово из 12 символов ≈ 800 lookup-ов ≈ 15 мс,
и только для слов, отсутствующих в словаре.

## 5. Фильтр галлюцинаций (`verification.GenerativeGuard`)

Фильтрация по **классу правки**, а не по имени категории:

| Класс | Решение |
|---|---|
| Отличие только пунктуацией/пробелами | разрешено |
| Исходное слово вне словаря (опечатка) | разрешено |
| Другая лемма при словарном исходном слове | отклонено |
| Падежная правка формы, согласованной в контексте | отклонено |
| Изменение чисел, дат, номеров пунктов | отклонено |
| Правка внутри сокращений и инициалов | отклонено |
| Изменение количества слов вне пунктуационного класса | отклонено |
| Различие только «ё»/«е» | отклонено |

Причины отказов видны в `/metrics` (`guard_rejections`) и в журнале на
уровне DEBUG — это делает поведение диагностируемым, чего в v8 не было.

## 6. Арбитраж (`verification.CandidateArbiter`)

Веса источников: `rule-* 1.00`, `dict-spell 0.94`, `languagetool 0.90`,
`russian-gec 0.86`, `sage 0.80`, `draft 0.66`.

* одинаковые правки от разных стадий сливаются, голоса суммируются
  (`+0.10` за каждое подтверждение);
* инфлективная правка от **одной** генеративной стадии без
  детерминированного подтверждения получает штраф `−0.25` и опускается
  ниже порога принятия `DECISION_MIN_CONFIDENCE=0.55`;
* детерминированное правило всегда выше любой модели.

## 7. Метрика качества (`eval/`)

90 предложений: 70 заведомо корректных (типовые конструкции служебных
документов: винительный падеж мужского неодушевлённого, причастные
обороты, однородные ряды, безличный пассив) и 20 с ошибками известных
классов.

Считаются: доля испорченных корректных предложений, точные совпадения,
token-level P/R и **F0.5** (в GEC точность весит вдвое больше полноты).

Детерминированный стек, без сети и без моделей:

| Метрика | v8 (`1ec8c62`) | v9 |
|---|---|---|
| Испорчено корректных предложений | 49 из 70 | **0 из 70** |
| Точных исправлений | 3 из 20 | **16 из 20** |
| Precision правок | 0.093 | **1.000** |
| Recall | 0.348 | **0.826** |
| F0.5 | 0.109 | **0.960** |

Базовая линия v8 воспроизводится на коде того коммита с тем же корпусом:

```bash
git archive 1ec8c62 | tar -x -C /tmp/v8 && cp server/local/eval/cases.jsonl /tmp/v8/server/local/
# далее прогнать LocalRuleEngine + DecisionEngine из /tmp/v8 по cases.jsonl
```

Запуск:

```bash
cd server/local
PYTHONPATH=..:. python -m eval.run_eval --verbose
PYTHONPATH=..:. python -m eval.run_eval --stack full   # с моделями
```

CI-гейт: `--max-fp 0 --min-exact 16`.

## 8. Что осталось за рамками детерминированного слоя

Честно фиксируем классы, где правил недостаточно и работают модели и
LanguageTool:

* именное управление без предлога («условия **хранение** оружия»);
* запятые при обособлении и однородных членах;
* стилистика и логика изложения.

Для пунктуации предпочтителен **LanguageTool** (900+ детерминированных
правил, офлайн, объяснимая причина каждой правки), а не генеративная
модель: правку пунктуации невозможно верифицировать морфологией, поэтому
она должна приходить из проверяемого источника.
