# Пользовательский словарь (v1.8b + v1.8.3)

Документ для **администратора** и **сотрудника**. Описывает, как работает
пользовательский словарь AI Suggester и как им пользоваться.

---

## Зачем

Модель T-lite-it-2.1 и morph-детектор (v1.8a) не знают:

- Внутренних аббревиатур организации (ЦСН, УФ, КС-2, ЦЛАТИ и т.п.).
- Специфических терминов отрасли (марки оборудования, шифры документов).
- Имён собственных, не входящих в стандартный словарь pymorphy3.

Раньше каждое такое слово приходилось добавлять отдельным PR-ом в код, либо
сервер «исправлял» его на похожее, что нельзя было откатить без новой
версии. **Теперь сотрудник сам добавляет термин кнопкой на панели**, и
сервер начинает считать слово корректным.

---

## Что делает сервер при добавлении слова

1. Слово сохраняется в `data/user_dict.json` (атомарная запись, потокобезопасно).
2. При каждом `/suggest`:
   - Слово инжектится в `SYSTEM_PROMPT` инструкцией: «Считать корректными следующие термины: ...» — модель уже не предлагает заменять их.
   - Если модель всё-таки предложила правку, где `before` или `after` содержит слово из словаря — этот пункт CHANGES удаляется (case-insensitive).
   - Morph-детектор (v1.8a) не флагит слова из словаря как OOV (неизвестные).

Технические детали — в `server/shared/user_dict.py` и `server/shared/morph_detector.py`.

## Использование сотрудником

На панели инструментов AI Suggester три кнопки:

| Кнопка | Действие |
|---|---|
| **AI: Улучшить текст** | Запустить проверку выделенного фрагмента. |
| **AI: В словарь** (v1.8b) | Быстрое добавление выделенного слова в словарь. |
| **AI: Словарь** (v1.8.3) | Диалог управления словарём (список + удаление + добавление). |

**Чтобы быстро добавить слово из документа:**

1. Выделить **одно слово** в документе (без пробелов, переносов строк).
2. Нажать кнопку **«AI: В словарь»** на панели.
3. Появится подтверждение: «Слово ... добавлено в словарь. Всего слов: N».

**Чтобы посмотреть словарь или удалить слово (v1.8.3):**

1. Нажать кнопку **«AI: Словарь»** на панели.
2. Откроется диалог со списком всех слов.
3. Для удаления: выделить одно или несколько слов в списке → «Удалить выделенные» → подтвердить.
4. Для добавления вручную (например аббревиатуры, которой нет в текущем документе): «Добавить новое...» → ввести слово.
5. Диалог автоматически обновляет список после каждого изменения. «Закрыть» → выход.

С этого момента модель и детектор считают эти слова корректными во всех
будущих проверках. Перезапуск сервера не нужен — словарь читается с диска
без перезагрузки.

### Ограничения

- Длина слова: **2–64 символа**.
- Только один токен (без пробелов, табов, переносов).
- Запрещённые символы: управляющие символы, кавычки `"`, обратный слэш `\`,
  угловые скобки `< >`, фигурные скобки `{ }`, квадратные скобки `[ ]`,
  обратные кавычки `` ` ``.
- Максимум **500 слов в словаре**. После лимита сервер отвечает HTTP 400.

## Legacy-макросы (до v1.8.3)

До v1.8.3 были два отдельных макроса, которые остаются поддерживаемыми
и доступны через «Сервис → Макросы → Мои макросы → ai_macro → Dict»:

| Макрос | Действие | Статус |
|---|---|---|
| `Dict.AIDictListWords` | Показать все слова (MsgBox). | Заменён на «AI: Словарь». |
| `Dict.AIDictRemoveWord` | Удалить слово (InputBox). | Заменён на «AI: Словарь» → «Удалить выделенные». |

Новый основной способ управления — кнопка **«AI: Словарь»** (m003).

## REST API сервера

Сотруднику этот раздел не нужен. Для интеграции/диагностики:

### `GET /dict/list`

Возвращает текущий список слов.

```bash
curl http://localhost:8000/dict/list
# {"words": ["ЦСН", "УФ", "КС-2"]}
```

Ответы:
- `200 OK` — JSON `{"words": ["...", "..."]}` (отсортирован).
- `503 Service Unavailable` — словарь отключён (`USER_DICT_ENABLED=false`).

### `POST /dict/add`

Добавляет слово.

```bash
curl -X POST -H "Content-Type: application/json" \
  -d '{"word":"ЦСН"}' http://localhost:8000/dict/add
# {"added": true, "total": 5}
```

Ответы:
- `200 OK` — `{"added": true|false, "total": N}`. `false` если слово уже было.
- `400 Bad Request` — невалидный ввод (формат / длина / запрещённые символы / лимит 500).
- `503 Service Unavailable` — словарь отключён.

### `POST /dict/remove`

Удаляет слово.

```bash
curl -X POST -H "Content-Type: application/json" \
  -d '{"word":"ЦСН"}' http://localhost:8000/dict/remove
# {"removed": true, "total": 4}
```

Ответы — аналогично `/dict/add`.

## Хранение и резервное копирование

- **Файл**: `data/user_dict.json` (или путь из `AI_SUGGESTER_USER_DICT_PATH`).
- **Формат**: JSON `{"words": [...], "updated_at": "ISO-8601"}`.
- **Атомарность**: запись через `tempfile` + `os.replace` — потеря данных
  при крэше исключена.
- **Резервная копия**: достаточно копировать сам `user_dict.json` (не более
  ~50 КБ при 500 словах). Бэкап рекомендуется делать вместе с
  `data/gec_bank.jsonl` и индексами.

## Откат / отключение

Чтобы временно отключить словарь, не теряя данные:

```bash
# .env.local или окружение сервера
USER_DICT_ENABLED=false
```

После рестарта сервера:
- REST-эндпоинты `/dict/*` отвечают 503.
- В `SYSTEM_PROMPT` ничего не инжектится.
- Morph-детектор работает без whitelist (может начать флагать аббревиатуры как OOV).
- Файл `data/user_dict.json` не трогается — можно вернуть в любой момент.

---

## Безопасность

- Слова валидируются на стороне сервера (`_validate_word`) — невозможно
  внести в `SYSTEM_PROMPT` newline / control char / SQL-подобный текст.
- При инжекте словарь форматируется как простой список через запятую внутри
  инструктивного предложения, не как code-block.
- Атомарная запись + блокировка (threading.Lock) — гонок не бывает.
